1.  Что такое Signal в Angular и какую проблему он решает?
    
    Signal - это реактивная обёртка над значением: Angular знает, какие шаблоны и вычисления его читают, и при изменении обновляет только их.

    Раньше Angular через Zone.js после любого события перепроверял всё дерево компонентов, потому что обычное свойство не сообщает, что оно изменилось. Signal делает проверку точечной, а производные значения (computed) кешируются и пересчитываются только при изменении зависимостей.

    Чем Signal принципиально отличается от обычного свойства класса?
    
    Отличие от обычного свойства:
    обычное свойство - просто данные, без отслеживания и уведомлений;
    signal читается как функция (count()), поэтому зависимости отслеживаются автоматически, а меняется через set()/update().


2.  Как работает signal()? Что происходит при чтении count() и при вызове count.set() / count.update()?

    создание - count = signal(0);
    count() - читает текущее значение сигнала.
    count.set(5) - полностью заменяет значение.
    count.update(...) - изменяет значение на основе текущего.

    И после set/update Angular уведомляет зависимые computed, effect и шаблоны, что значение изменилось.


3.  Что такое dependency tracking? Как Angular понимает, от каких Signals зависит конкретный computed или effect?

    Dependency tracking — это механизм, с помощью которого Angular запоминает: «этот computed/effect использует вот эти Signals».

    Signal читается внутри computed/effect → Angular автоматически запоминает эту зависимость. Причём зависимости определяются динамически во время выполнения, а не прописываются вручную.


4.  Чем computed() отличается от effect()? Когда нужно использовать каждый из них? 
    
    computed() - используем, когда нужно получить новое значение из существующих Signals.

    effect() - используем, когда нужно выполнить побочное действие при изменении Signals.

    Приведи пример неправильного использования effect.
    
    Неправильное использование effect:

    total = signal(0);
    effect(() => {
      this.total.set(this.price() * this.quantity());
    });
     - Здесь total является производным значением от price и quantity.


5.  Что такое memoization в computed() и зачем она нужна?
    
    Memoization в computed() — это когда Angular запоминает (кеширует) результат вычисления, чтобы не считать его заново без необходимости.

    Когда computed пересчитывает своё значение, а когда возвращает закешированное?

    computed пересчитает значение, только если изменился Signal, который он использует.
    Если Signal не менялся, то вычисление повторно не выполняется, возвращается кешированный результат.

    computed() = вычисляет только когда его зависимости изменились + кеширует результат между пересчётами.


6.  Что произойдет, если внутри effect() прочитать несколько Signals? Все ли они станут dependencies?

    Все Signals, которые effect() прочитал во время выполнения, становятся его dependencies.
    Если изменится любой из Signals (которые внутри effect()) → effect() запустится снова.
    
    Что такое untracked() и зачем он нужен?
    
    Функция untracked() используется для чтения значения реактивного сигнала (Signal) без создания автоматической зависимости. untracked() говорит Angular:«Прочитай этот Signal, но НЕ добавляй его в dependencies».
    untracked() нужен когда нужно прочитать значение Signal, но не нужно, чтобы изменение этого Signal запускало effect().


7.  Как Signals взаимодействуют с Change Detection?
    
    Взаимодействие: шаблон компонента - это потребитель signals. При рендере Angular запоминает, какие signals он прочитал. Когда один из них меняется, компонент помечается как требующий проверки, и Angular обновляет только его, а не всё дерево.

    Signals помогают Angular точнее запускать обновление UI. Если компонент читает signal в шаблоне:count = signal(0);
    <p>{{ count() }}</p> Angular запоминает зависимость: этот компонент использует count. Когда вызвать: this.count.set(1);
    Angular помечает только зависимый компонент для проверки и при следующем Change Detection обновляет DOM. Это особенно полезно с OnPush: не нужно вручную вызывать markForCheck().
    Идея: обычный Change Detection может проверять много компонентов, а Signals позволяют Angular знать, что именно изменилось и где это используется, поэтому обновления становятся более точечными.

    Что происходит, если Signal прочитан в template компонента с OnPush, а затем его значение изменилось?
    
    Angular автоматически помечает этот OnPush-компонент как нуждающийся в проверке (dirty).
    То есть, если signal был прочитан в шаблоне: - name = signal('Anna');
    <p>{{ name() }}</p>
    а потом значение изменилось: - this.name.set('Maria');
    Angular знает, что данный шаблон зависит от name, запускает проверку нужного компонента и обновляет DOM до Maria. Вручную вызывать ChangeDetectorRef.markForCheck() не нужно — signal делает это автоматически.


8.  Чем Signals отличаются от RxJS Observable?

                 Signal                                Observable
    | ---------------------------- | -------------------------------------------------------- |
    | Хранит **текущее состояние** | Представляет **поток значений/событий во времени**       |
    | Получаем `count()`           | Получаем через `subscribe()` / `async`                   |
    | Есть текущее значение        | Текущего значения может не быть                          |
    | `set()` / `update()`         | `next()` у Subject или события источника                 |
    | Отлично для состояния UI     | Отлично для async-потоков, HTTP, событий                 |
    | `computed()`                 | RxJS-операторы `map`, `switchMap`, `debounceTime` и т.д. |

    В каких ситуациях ты выберешь Signal, а в каких Observable?
    
    Signal - когда мне нужно хранить состояние приложения или компонента:

      isLoading = signal(false);
      count = signal(0);

      Например:
        открыт ли модал;
        выбранный пользователь;
        состояние кнопки;
        значение формы/фильтра;
        вычисляемое состояние через computed().

    Observable - когда у меня есть поток событий или асинхронных данных:

      search$.pipe(
        debounceTime(300),
        switchMap(...)
      )

      Например:
        HTTP-запросы;
        поиск с debounce;
        WebSocket;
        события во времени;
        сложные цепочки async-операций;
        Subject / BehaviorSubject.
        Очень простая аналогия

      Signal - «Какое значение сейчас?»

      Observable - «Какие значения приходят и что с ними делать по мере поступления?»

      В современном Angular необязательно выбирать что-то одно. Например, HTTP можно получать через Observable, а результат хранить/представлять в UI через Signal.


9.  Как связать Signals и RxJS? Для чего нужны toSignal() и toObservable()?

    Angular даёт два основных моста между Signals и RxJS:
    toSignal() — Observable → Signal
    и
    toObservable() — Signal → Observable

    схема:
    Observable ── toSignal() ──→ Signal
    Signal ── toObservable() ──→ Observable

    toSignal() — хочу работать с Observable как с Signal.
    toObservable() — хочу использовать Signal внутри RxJS-цепочки.

    Какие проблемы могут возникнуть при использовании toSignal() без initialValue?

    Главная проблема: до первого значения Observable Signal может быть undefined.
    Без initialValue: - Observable ещё ничего не дал → Signal может быть undefined.
    С initialValue: - пока Observable не дал данные → используется указанное начальное значение.

    Особенно важно для template, чтобы не получить ошибку при обращении к данным, которых ещё нет.

10. Что произойдет в следующем коде и сколько раз пересчитается fullName?

    Если fullName() нигде не вызывается, то computed вообще не пересчитается.
    Если один раз вызвать fullName(); то computed вычислится 1 раз и вернёт- John Doe.
    
    Итого: 1 вычисление — только если fullName() прочитали. Если не прочитали — 0.
